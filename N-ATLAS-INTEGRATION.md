# N-ATLAS integration

How the N-ATLAS Sovereign Gateway integrates with N-ATLAS, how to verify it, and the evidence produced.

## What the gateway integrates with

| | |
|---|---|
| Model | **N-ATLaS** (`NCAIR1/N-ATLaS` on Hugging Face), Llama-3 8B fine-tuned for English, Yoruba, Hausa and Igbo by NCAIR/NITDA with Awarri Technologies |
| Interface | OpenAI-compatible Chat Completions (`/v1/chat/completions`), streaming and non-streaming, as exposed by vLLM, Ollama, Hugging Face TGI or a hosted provider |
| Served model name | `n-atlas-8b` (clients send this; the gateway maps it to the upstream's model name via `UPSTREAM_MODEL`) |
| Where it plugs in | [`src/upstream/client.ts`](src/upstream/client.ts) (network-shielded calls), [`src/upstream/registry.ts`](src/upstream/registry.ts) (hot-swappable, validated endpoint) |

The gateway does not wrap any other general-purpose model. Without a GPU attached it falls back to a clearly labelled **mock** (the dashboard header shows an amber "Upstream: mock N-ATLAS" badge; with the real model it turns green and names the deployment).

## What is N-ATLAS-specific

- **Languages N-ATLAS serves are first-class.** Every prompt is labelled Yoruba, Hausa, Igbo, Nigerian Pidgin or English ([`src/lib/language.ts`](src/lib/language.ts)), returned as `x-natlas-language`, counted in stats and in the audit trail. The semantic cache never reuses an answer across languages.
- **Jailbreak defence in N-ATLAS languages**, including Pidgin, Yoruba, Hausa and Igbo phrasings, and Llama-3 chat-template role tokens (`<|start_header_id|>`, `<|eot_id|>`), which matter because N-ATLaS uses the Llama-3 template.
- **Nigerian personal data** (BVN, NIN, NUBAN, FRSC licence, PVC VIN, Nigerian phones, Lagos/Abuja addresses and GPS) is removed before N-ATLAS sees a prompt and restored in its answer.

## Running the official weights

### Option A: free Colab GPU (about 10 minutes)

1. Accept the terms at https://huggingface.co/NCAIR1/N-ATLaS and create a read token.
2. Open [`deploy/colab/natlas_vllm_colab.ipynb`](deploy/colab/natlas_vllm_colab.ipynb) in Google Colab, choose a T4 GPU, add the token as the secret `HF_TOKEN`, and run all cells. It serves N-ATLaS with Hugging Face transformers in 4-bit (fits a free T4), sanity-checks Yoruba, Hausa, Igbo and Pidgin, and prints a public URL and key.
3. Point the running gateway at it, with no redeploy. The gateway calls the endpoint once to validate it before switching, and remembers the choice across restarts:

```bash
curl -X POST https://natlas-gateway.onrender.com/admin/upstream \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H "Content-Type: application/json" \
  -d '{"url":"https://<tunnel>.trycloudflare.com/v1","apiKey":"<printed key>","model":"n-atlas-8b","label":"NCAIR1/N-ATLaS on vLLM (Colab GPU)"}'
```

### Option B: your own GPU server

```bash
vllm serve NCAIR1/N-ATLaS --served-model-name n-atlas-8b --max-model-len 8192 --api-key <key>
# then POST /admin/upstream as above, or set UPSTREAM_URL / UPSTREAM_API_KEY / UPSTREAM_MODEL
```

### Option C: N-ATLAS API credentials from NCAIR

Shortlisted teams receive N-ATLAS API credentials. If the endpoint is OpenAI-compatible, it is one `POST /admin/upstream` call; otherwise a small adapter goes in `src/upstream/client.ts`.

## How to verify the integration

1. `GET /healthz` returns the active upstream: `{"upstream":{"mode":"n-atlas","provider":"…","model":"n-atlas-8b"}}`.
2. `npm run evidence` (set `GATEWAY_URL` to the live gateway) sends Yoruba, Hausa, Igbo, Pidgin and PII-heavy prompts through the full pipeline and writes **`natlas-evidence.md`**, with each prompt, **exactly what N-ATLAS received** (redacted), the answer, the upstream model id, the detected language, redactions and per-stage timings.
3. In the dashboard playground, the *What N-ATLAS saw* pane shows the redacted prompt for every request, and the X-ray shows the time spent inside N-ATLAS.
4. `npm run bench` compares N-ATLAS direct, through the gateway, and from cache, and writes `bench-results.md`.

## Evidence

- `natlas-evidence.md`: generated by `npm run evidence` against the live gateway once the official model is attached.
- `bench-results.md`: latency benchmark.
- `/admin/report`: NDPA compliance report from the hash-chained audit trail.
- `/beta`: external testers, their audited usage, and their feedback.
